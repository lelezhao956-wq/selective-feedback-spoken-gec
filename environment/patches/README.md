# Patches to the official S&I 2025 baseline code — what to apply

Added 2026-11-12 after the reproduction audit (`docs/AUDIT_REPORT.md`, defect 16), i.e. a pre-submission reproduction audit, run in a separate workspace with freshly created environments and following only the package documentation; the audit was carried out with an AI coding assistant (see the declaration of generative AI use in the manuscript). Nothing in this folder was
removed; the files fall into three groups.

Version 5: the 11 patches of group A are zero-context diffs (`diff -U0`): they contain only the changed lines, not the
surrounding official code (the official baseline states no licence, see "Licence of these files"). Verified: applied to the
unmodified files from the official zips, they give files byte-identical to the patched files used in the study (11/11).

## A. Apply these 11 patches (portability: macOS / Apple Silicon, CPU)
Unpack the official `baseline-pipeline.zip` and `scoring-tools.zip` into a working directory (a copy, never the corpus
originals), copy `envs/` and `check-pipeline.sh` from the corpus, then from that directory run, for each file below,
`patch -p0 -b < <this folder>/<file>` (`-b` keeps `*.orig` backups; `orig_files.txt` lists the 11 backups this produces).

| patch | patched file |
|---|---|
| `baseline-pipeline_gec-tools_dd.py.diff` | `baseline-pipeline/gec-tools/dd.py` |
| `baseline-pipeline_gec-tools_gec-plus-align.py.diff` | `baseline-pipeline/gec-tools/gec-plus-align.py` |
| `baseline-pipeline_run-scripts_run-asr-decode.sh.diff` | `baseline-pipeline/run-scripts/run-asr-decode.sh` |
| `baseline-pipeline_run-scripts_run-asr-to-task-input.sh.diff` | `baseline-pipeline/run-scripts/run-asr-to-task-input.sh` |
| `baseline-pipeline_run-scripts_run-gec.sh.diff` | `baseline-pipeline/run-scripts/run-gec.sh` |
| `baseline-pipeline_run-scripts_run-sla.sh.diff` | `baseline-pipeline/run-scripts/run-sla.sh` |
| `baseline-pipeline_sla-tools_inference_sla.py.diff` | `baseline-pipeline/sla-tools/inference_sla.py` |
| `check-pipeline.sh.diff` | `check-pipeline.sh` |
| `envs_sandi-all-env.sh.diff` | `envs/sandi-all-env.sh` |
| `envs_sandi-dd-env.sh.diff` | `envs/sandi-dd-env.sh` |
| `scoring-tools_run-scripts_run-wer-scoring.sh.diff` | `scoring-tools/run-scripts/run-wer-scoring.sh` |

If your conda environments have other names than `sandi-all` / `sandi-dd`, edit the `conda activate` line of the two patched
`envs/*.sh` files accordingly (the study scripts take the names from `ENV_SANDI_ALL` / `ENV_SANDI_DD`, see `scripts/paths.sh`).

## B. Build records — do NOT apply
`sctk-2.4.9_text_changes.diff`, `sctk-2.4.9_asclite_text_changes.diff`, `sctk-2.4.9_vs_orig.filelist.txt`,
`tranfilt-1.14_vs_orig.filelist.txt`: what rebuilding SCTK 2.4.9 and tranfilt 1.14 changed in the source tree (mostly files
regenerated by `make`). They document the result of the rebuild described in `../mac_changes.md`; reproduce them by following
that file (the reproduction audit's rebuild produced the same set of changed files, and the same `rfilter1` sha256).

## C. Notes, not patches — ignore
`scoring-tools_wer-tools_sctk-2.4.9_src_md-eval_test_md_test25.output.diff` and
`scoring-tools_wer-tools_sctk-2.4.9.orig_src_md-eval_test_md_test25.output.diff` contain only the note "INVALID":
`md_test25.output.orig` is a test fixture shipped inside SCTK, not a backup made by us.
(Both note files are distributed from package version 4 on; version 3 left out the second one by mistake.)
